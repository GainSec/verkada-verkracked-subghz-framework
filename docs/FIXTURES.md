# Fixture policy

`fixtures/manifest.json` is the public fixture inventory. The generated EFR32
corpus has an additional per-file manifest under `research/efr32/corpus/`.

## Terms

- **Synthetic fixture**: created entirely from deliberate example values.
- **Independently reconstructed fixture**: recreated from a protocol/model
  description using independent code; it is not a raw capture.
- **Observed fixture**: exact bytes recorded during an authorized observation.
- **Captured fixture**: raw or derived acquisition from physical hardware/RF.
- **Golden vector**: a stable expected value used by regression tests; this
  label says nothing about its origin.
- **Analytical vector**: model output not established as physically exact.

The retained public fixtures are synthetic or independently reconstructed.
None is labeled observed, captured, or physically validated.

`fixtures/session/synthetic-join-public.json` contains deliberate example
identities, public keys, join bodies, counters, and expected digests for
portable regression tests. It contains no private scalar or live session key.

## Adding vectors

1. Prefer a minimal synthetic vector generated by public source code.
2. Remove or replace EUIs, PAN identifiers, serial-derived fields, counters,
   keys, receiver serials, timestamps, locations, and infrastructure metadata.
3. Add the path, provenance classification, description, SHA-256, identifier
   status, exact-observation status, analytical status, and physical-validation
   status to the manifest.
4. Add or update a reproducibility test.
5. Never relabel synthetic data as observed, or analytical data as physically
   validated.

Captured data requires explicit maintainer provenance/release review. Do not
open a public pull request containing a private capture. Category-D
vendor-derived data and unknown-provenance data are not accepted.
